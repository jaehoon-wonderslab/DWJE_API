### A-6. S110 에 대한 판단

- 역산은 성립한다. 재현율은 어떤 기준으로도 97~100%, 단일 항목 환원 69~89%, 확정 세트 오탐 0.
- 한계 세트는 **(작업장, 설비)** 단위여야 한다. GP-015 가 다른 규격을 쓴다. 제품 열이 없어(컬럼 108개 = 키 7 + FAI 100 + PASSED/COMMENT/DATE_TIME) 제품별로는 못 나눈다.
- 하한이 중요하다(이탈의 62%). S120 처럼 상한만 보면 놓친다.
- 포화 판정 단계 폭은 **분해능**을 따라야 한다 — S110 0.0001, S120 0.001. FAI 값의 소수 자릿수로 정한다.
- 확정되는 항목 수는 표본 기간에 비례한다. 3일로 실질 5개(FAI1·15·16·17·34), 7일이면 FAI29 등 추가.

## B. `ax.tb_aoi_dim_daily` 설계안 (만들지 않음 — 5차에서 접힘)
> **2026-09-13 (5차) — B 절의 요약 테이블 3개와 적재 배치는 만들지 않는다.** 원천이 실시간 IO 가 많은 표라 주기 배치가 장애를 만들 수 있다는
> 현업 판단(기획 결정 13)으로 접었다. 조회 시점에 MSSQL 을 직접 읽는 구현과 그 실측은 `AOI_DIMENSION_API_20260913.md`. 아래 설계는 **근거 기록**으로만 남긴다.


### B-1. 왜 미리 만들어야 하나 — 실측

| 작업 (원격, 인덱스 없음) | 시간 |
| :--- | ---: |
| S120 하루 전체(설비 5, 210,328행) 측정 수·불량 수 집계 | 43초 |
| 같은 하루 불량 행(21,000행)만 읽어 확정 한계 10개 위반 건수·초과량 합 (설비×FAI 53행) | 42초 |
| 설비 하루 6만 행 UNPIVOT·백분위·검증 (3차 절차 전체) | 46초 |

브리핑은 조회할 때마다 1~2초 안에 나와야 하므로 **원천을 조회 시점에 읽는 설계는 불가**하다. 일자·작업장·설비 단위로 미리 집계해 PostgreSQL 에 두고,
API 는 그 표만 읽는다(30일 × 설비 12 = 360행, FAI 별 21,000행 → 100ms 안).

### B-2. 테이블 3개

**① `ax.tb_aoi_dim_limit` — 한계 세트 (테이블 신설 권장, 설정 파일 아님)**

| 컬럼 | 타입 | 뜻 |
| :--- | :--- | :--- |
| `limit_id` | bigserial PK | |
| `wc_cd` · `eqpt_cd` | varchar | 세트 단위 = (작업장, 설비). S120 은 설비끼리 같은 값이 나온다 |
| `fai_no` | smallint | 1~100 |
| `usl` · `lsl` | numeric(12,4) | 확정된 값만. 없으면 NULL |
| `usl_state` · `lsl_state` | varchar(10) | `CONFIRMED`(포화+간격 규칙 통과) · `MANUAL`(현업 입력) · `NONE` |
| `resolution` | numeric(8,4) | 0.001 / 0.0001 — 포화 판정 단계 |
| `basis_from` · `basis_to` | date | 산출에 쓴 합격 행 기간 (7일 권장) |
| `pass_at_usl_cnt` · `pass_at_lsl_cnt` | int | 한계값에 정확히 놓인 합격 행 수 (확정 근거) |
| `fail_gap_usl` · `fail_gap_lsl` | numeric(12,4) | 불량 최솟값 − USL / LSL − 불량 최댓값 (= resolution 이어야 확정) |
| `pass_max` · `pass_min` · `pass_cnt` | numeric / int | 참고용 산포 |
| `valid_from` · `valid_to` | timestamptz | 세트 버전 — 갱신할 때 이전 행을 닫는다(이력) |
| `computed_at` · `ins_user` … | | 표준 감사 컬럼 |

설정(yml/코드)이 아닌 **테이블**인 이유: (작업장, 설비, FAI) 2,000행 규모로 값이 데이터에서 매주 갱신되고, 이력·근거(포화 건수·간격)를 남겨야 하며,
현업이 도면 값을 알게 되면 `MANUAL` 로 덮어써야 한다(그때 `CONFIRMED` 산출값과 대조도 가능). 설정 파일은 이 셋을 다 못 한다.

확정 규칙(배치): 최근 7일 (작업장, 설비) 합격 행의 FAI 별 max·min → 불량 행 중 max 초과분의 최솟값이 `max + resolution` 이고 `pass_at_max ≥ 20` 이면 USL 확정.
하한도 같은 식. 확정되지 않으면 NULL(NONE). 세트가 바뀌면 새 버전을 열고, 일자 요약에는 쓴 버전을 남긴다.

**② `ax.tb_aoi_dim_daily` — 일자 × 작업장 × 설비 (화면 (가)(다)(라))**

| 컬럼 | 뜻 |
| :--- | :--- |
| `meas_date` · `wc_cd` · `eqpt_cd` | PK. `DATE_TIME` 기준 일자 (`>= d AND < d+1`) |
| `meas_cnt` · `pass_cnt` · `fail_cnt` | 측정(SEQ) 수·합격·불량 → 불량률 = fail/meas |
| `serial_cnt` · `serial_fail_cnt` | 그날 관측된 시리얼 수 · 불량 SEQ 를 가진 시리얼 수 (참고 — 3차 실측대로 거의 전부 불량) |
| `fail_single_cnt` | 확정 한계 위반 FAI 가 정확히 1개인 불량 행 |
| `fail_multi_cnt` | 2개 이상 |
| `fail_unconfirmed_cnt` | 확정 한계 위반 0개 (미확정 항목 이탈) |
| `fail_zero_cnt` | 측정 실패 (비영 FAI ≤ 5개). 위 세 범주보다 **먼저** 판정해 겹치지 않게 한다 |
| `limit_id_min` · `limit_id_max` 또는 `limit_ver` | 판정에 쓴 한계 세트 버전 |
| `first_at` · `last_at` | 그날 첫·마지막 측정 시각 |
| `loaded_at` · `load_state` | 적재 시각 · `PARTIAL`(당일 진행 중) / `FINAL` |

설명률(라) = (single + multi) / fail_cnt. 귀속 유형(다) = 위 네 카운트. 직전 동일 기간 대비(마)는 같은 표를 기간만 옮겨 두 번 읽으면 되므로 열이 필요 없다.

**③ `ax.tb_aoi_dim_daily_fai` — 일자 × 작업장 × 설비 × FAI (화면 (나))**

| 컬럼 | 뜻 |
| :--- | :--- |
| `meas_date` · `wc_cd` · `eqpt_cd` · `fai_no` | PK |
| `viol_cnt` | 이 FAI 가 확정 한계를 벗어난 불량 행 수 |
| `viol_single_cnt` | 그중 이 FAI 만 벗어난 행 수 (단일 귀속 건수 — 브리핑의 "88% 가 FAI23" 은 이 값) |

| `exceed_sum` · `exceed_max` | 초과량 합·최대 (평균 = sum / viol_cnt, 기간 합산도 sum 끼리 더하면 된다) |

| `pass_max` · `pass_min` · `pass_at_usl_cnt` · `pass_at_lsl_cnt` | 그날 합격 산포 — 다음 주 한계 재확정의 재료(원천을 다시 읽지 않게) |

| 초기 적재 | 1회 | 최근 30~90일 | 하루 3분 × 90일 ≈ 4.5시간, 야간 분할 |

배치는 **MES 마이그레이션 엔진**에 두는 것을 권한다 — 이미 MSSQL 원천 접속·스케줄·PostgreSQL 적재 경로를 갖고 있고, API 에는 MSSQL 드라이버가 없다.
API 는 `ax.*` 세 표만 읽는다. 원천 읽기는 `DATE_TIME >= @d AND DATE_TIME < @d+1` 로 걸고, 불량 행에서만 `FAI*` 를 읽어 UNPIVOT 한다(합격 행은 min/max 만 — 3차 문서 4절의 커버링 인덱스 요청이 있으면 43초 → 수 초).

### B-4. 브리핑 조회 API 가 이 표에서 뽑는 것 (다음 요청 때 확정)

```
기간·작업장·설비 →
  (가) Σ meas_cnt, Σ fail_cnt, 불량률
  (나) FAI 별 Σ viol_cnt, Σ viol_single_cnt, Σ exceed_sum / Σ viol_cnt, usl/lsl (기간 마지막 스냅샷)
  (다) Σ fail_single/multi/unconfirmed/zero
  (라) (single+multi) / fail
  (마) 같은 길이의 직전 기간을 한 번 더 읽어 차이·증감률
```
FAI 이름은 없다(현업 (b) 확정) — 번호와 한계값까지만 문장에 넣는다.

## C. 남은 전제

- (작업장, 설비) 세트 확정 규칙의 `pass_at ≥ 20`·`gap = resolution` 기준값은 7일 표본으로 한 번 더 검증한 뒤 고정한다(이번은 3일·하루 표본).
- GP-015 처럼 규격이 다른 설비가 **같은 설비에서 시기별로** 바뀔 수 있는지(제품 교체)는 더 긴 기간을 봐야 안다. 바뀐다면 세트 버전이 자주 열리고, 그 자체가 "제품 교체 시점" 신호가 된다.
- 커버링 인덱스(3차 문서)는 여전히 덕우전자 전산 요청 사안이다. 없어도 배치는 돌지만 시간당 갱신이 1분 안팎 걸린다.
